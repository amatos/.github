# Contributing

Thanks for taking the time to improve one of my projects.

These repositories are primarily maintained by a single developer, so the most
helpful contributions are focused, reproducible, and easy to review.

## Issues

Before opening an issue, check whether an existing issue already covers it. When
filing a new one, include enough context for someone else to reproduce or reason
about the problem.

For bug reports, include:

- What happened.
- What you expected to happen.
- Steps to reproduce.
- Relevant versions, environment details, logs, or screenshots.

For feature requests, include:

- The problem or use case.
- The behavior you want.
- Alternatives you considered.

## Pull Requests

Pull requests are easiest to review when they are small and direct.

Before opening a PR:

- Keep unrelated changes out of the branch.
- Add or update tests when behavior changes.
- Update documentation when usage changes.
- Run the relevant local checks for the project.

If a project has its own contributing guide, follow that instead.

## Style

Prefer the existing style of the repository over introducing a new convention.
Use the formatter, linter, package manager, and test runner already present in
the project.
